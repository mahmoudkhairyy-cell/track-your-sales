# دستور مشروع Track Your Sales

مصدر الدستور: `README.md`، و`DEPLOYMENT.md`، و`CONTENT_STYLE_GUIDE.md` في الريبو. أي تعارض بين الدستور والكود يتحل بمراجعة الدستور مع صاحب المشروع قبل أي تغيير.

## المبادئ الأساسية

### I. البيانات أولاً وعلى الجهاز
- بيانات المستخدم محفوظة محليًا في `localStorage` (المفتاح `trackYourSales.local.v1`).
- ممنوع مسح بيانات المستخدم أو تفريغ `localStorage` إلا بطلب صريح وتأكيد من صاحب المشروع.
- أي تغيير في الاستعادة أو الدمج لازم يحافظ على البيانات الموجودة، ويعرض التعارض بدل ما يكتب فوقه بصمت.
- النسخ الاحتياطي JSON هو المصدر المعتمد لنقل البيانات بين الأجهزة.

### II. قواعد الحساب ثابتة
- معادلات التارجت والكوميشن والأوزان ما بتتغيرش من غير موافقة صريحة.
- كل KPI له وزن وتارجت: أقل من 90% لا يساهم في الإجمالي، وعند 90% يبدأ احتساب مساهمته.
- لا سقف 200% للمؤشرات الفردية، والسقف 200% للإجمالي الشهري فقط.
- New Orange Cash وزنه 0%، وهو شرط مستقل لاستحقاق الكوميشن (المحافظ الجديدة لا تقل عن 90% من New Lines).
- لا يُحتسب الكوميشن إلا لو الإجمالي النهائي 80% أو أكتر.
- الكوميشن لازم يفضل ظاهر للمستخدم.
- القيم المدخلة (التارجت والأوزان والكوميشن) لازم تكون صفر أو أكبر قبل أي كتابة.

### III. الاختبارات قبل النشر
- `npm run selfcheck` و`npm run typecheck` و`npm run lint` و`npm run build` لازم تنجح قبل أي نشر.
- الـ deploy على GitHub Pages لازم يعتمد على نجاح `build` و`backend-test` معًا.
- أي تغيير في منطق الدمج أو الاستعادة لازم يتغطى بتجربة: استيراد نفس الملف مرتين، ويومين بنفس المبيعات، ونسخة أقدم، وملف تالف.

### IV. النشر بموافقة
- النشر على `local-version` بيشغل GitHub Pages، فممنوع أي push للنشر من غير موافقة صريحة من صاحب المشروع في الحالات اللي مطلوب فيها مراجعة.
- الفرع الأساسي للعمل هو `local-version` فقط. ممنوع العمل على `main` أو مشاريع تانية.
- كل بند في commit منفصل برسالة واضحة.

### V. الخصوصية
- ملاحظات المستخدم الشخصية ما بتتبعتش للسيرفر.
- ممنوع وضع مفاتيح سرية أو `.env` أو نسخ JSON احتياطية داخل المستودع.
- مفاتيح الخدمة (Supabase service key) والأسرار تفضل في متغيرات البيئة بس.

### VI. النبرة واللغة
- الواجهة عربية RTL، والضمير "إنت" المباشر، ممنوع "حضرتك".
- الأرقام توضح وحدتها.
- رسائل الأخطاء التقنية بدون فكاهة، ومن غير اعتذار زيادة.
- الدليل الكامل في `CONTENT_STYLE_GUIDE.md`.

### VII. مرجع الـ SR
- أي كود SR أو وصف مش متأكد منه لازم يتعلم عليه `[تحتاج مراجعة]` لحد ما يتأكد من المرجع الداخلي.
- ممنوع اختراع خطوات أو أكواد غير موجودة في المصادر.

## قيود التطوير
- الكود Static Export: مفيش خادم Next.js أو PostgreSQL في التطبيق الأساسي.
- مزامنة تقارير المدير عن طريق Supabase Edge Function منفصلة، والتطبيق نفسه ما يتوقفش لو المزامنة مش مفعّلة.

## الحوكمة
- أي تعديل على الدستور لازم يتعمل بـ commit منفصل ويتوثق سببه في رسالة الـ commit.
- عند التعارض بين طلب جديد وأي مبدأ هنا، يُسأل صاحب المشروع قبل التنفيذ.
